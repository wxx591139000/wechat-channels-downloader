# 协作开发指南（给协作者）

> 项目：微信视频号下载器（sphdl）
> 仓库：https://github.com/wxx591139000/wechat-channels-downloader
> 本文档面向协作者，讲清怎么克隆、怎么改、怎么提 PR。

## 一、怎么拿到代码

### 第 1 步：Fork 到自己账号

打开 https://github.com/wxx591139000/wechat-channels-downloader

点右上角的 **Fork** 按钮 → 选择自己的账号 → 等几秒，你就有了
`https://github.com/<你的用户名>/wechat-channels-downloader`

### 第 2 步：克隆你的 Fork

```bash
git clone https://github.com/<你的用户名>/wechat-channels-downloader.git
cd wechat-channels-downloader
```

> ⚠️ **仓库有 545MB**（历史里留了几个 30MB 的旧版 exe 包）。
> 网络慢的话可以只拉最新一次提交：
> ```bash
> git clone --depth 1 https://github.com/<你的用户名>/wechat-channels-downloader.git
> ```
> 但 `--depth 1` 之后提 PR 可能需要先 `git fetch --unshallow`。

### 第 3 步：加上游仓库（重要，用于同步主仓库更新）

```bash
git remote add upstream https://github.com/wxx591139000/wechat-channels-downloader.git
git remote -v
# 应该看到：
#   origin    https://github.com/<你>/wechat-channels-downloader.git  (你的 fork)
#   upstream  https://github.com/wxx591139000/wechat-channels-downloader.git  (主仓库)
```

## 三、搭开发环境

### 需要什么

| 项 | 版本 |
|---|---|
| Windows | 10 / 11 64 位 |
| Python | 3.11 |
| 依赖 | mitmproxy 11、PyInstaller 6.x、Pillow、cryptography |

### 安装

```bash
# 在 sphdl 的同级目录建虚拟环境（推荐，与原作者的 .venv 结构一致）
cd wechat-channels-downloader
python -m venv .venv

# 激活（Git Bash）
source .venv/Scripts/activate
# 或 CMD
.venv\Scripts\activate.bat

# 装依赖
pip install mitmproxy pyinstaller pillow cryptography requests
```

> ⚠️ **必须用 venv 里的 python**，系统 Python 缺 mitmproxy 会起不来嗅探。

### 跑起来

```bash
cd sphdl
python main.py --gui
```

## 四、⚠️ 授权密钥问题（协作者必读）

**源码里没有密钥**，这是**故意的**（否则谁都能造授权码）。

### 影响

1. **自己跑 GUI 时授权码功能不可用** —— 你粘任何码都会显示"无效"
   （因为缺 `sphdl/_lic_key.py`）
2. **不能自己造码测试** —— 需要联系原作者要一个测试码
3. **不影响的部分**：嗅探、下载、解密、公众号解析、界面布局
   —— 这些都能正常开发调试

### 怎么测试授权相关功能

**方式 A（推荐给协作者）**：找原作者要一个**测试用授权码**，
粘进软件即可（码本身自带校验数据，客户端不需要密钥就能验证真码）。

**方式 B（只有原作者能做）**：从 `.license_secret` 导出 `_lic_key.py`
—— 这个文件**绝不入库**，也不该发给别人。

### 所以协作者能做什么

| 能做 | 不能做 |
|---|---|
| 修嗅探/下载/解密/解析的 bug | 生成新的授权码 |
| 改界面、改交互 | 自己造码测授权流程 |
| 改文档、写测试 | 改发码后台的密钥逻辑（改了也没法验证） |

## 五、开发流程

### 1. 先同步主仓库最新代码

```bash
git checkout main
git fetch upstream
git merge upstream/main        # 或 git rebase upstream/main
git push origin main
```

### 2. 建分支（不要直接在 main 上改）

```bash
git checkout -b fix/xxx-bug
# 或 feature/xxx-feature
```

### 3. 改代码

**改完要跑测试**：

```bash
cd sphdl
# 最快的关键回归（15 项，改任何核心代码都必跑）
python tests/test_sniff_smoke.py

# 离线基础（11 项）
python tests/test_offline.py

# 其他按改动范围挑
python tests/verify_batch_driver.py       # 改批量驱动
python tests/verify_seen_release.py       # 改去重/删记录
python tests/verify_unified_list.py       # 改列表/筛选
python tests/verify_mp_article.py         # 改公众号解析
```

> ⚠️ 部分测试需要 `_lic_key.py`（授权相关），缺它会报"未注入授权密钥"。
> 那是**正常的**——那些测试只能原作者跑。你跑不需要密钥的那几套即可。

### 4. 提交

```bash
git add <明确列出的文件>          # ⚠️ 不要用 git add -A / git add .
git commit -m "fix: 修复 XXX 问题

现象：...
根因：...
修法：..."
git push origin fix/xxx-bug
```

> ⚠️ **绝对不要 `git add -A`**。历史上有过一次事故：`.gitignore` 的通配例外
> 让 `git add -A` 把 17 个 30MB 的 zip 全提交了（540MB）。
> **永远用显式文件列表**。

### 5. 提 Pull Request

在 GitHub 上打开你的 fork，会看到 "Compare & pull request" 按钮 → 点它。

PR 描述建议写清：

```markdown
## 问题
（用户看到什么现象）

## 根因
（技术原因）

## 修法
（怎么改的）

## 测试
（跑了哪些测试，结果如何）
```

## 六、代码规范（跟现有风格保持一致）

### 注释要写"为什么"

这个项目里所有非显然的代码都写清了原因。例如：

```python
# ★ v2.1.7：未授权（max_records <= 0）不再"永不满档"，改为按
#   `UNLICENSED_CAPTURE_LIMIT`（500 条）封顶。原因见 config.py 的说明：
#   完全不限会让客户抓几万条，排序 5 万条要 38 秒（PITFALLS #7），
#   界面会卡死。500 条足够看清工具确实有用，又不会拖慢。
```

**不写"这一行做了什么"（代码本身说明了），要写"为什么这样写"。**

### 版本标记

大改动加 `★ vX.Y.Z：` 前缀，方便以后追溯。

### 改动前先看 PITFALLS

`docs/PITFALLS.md` 有 **66 条**实战踩过的坑，每条都是真实事故。
**改任何相关代码前先 grep 一遍**，能避免重复踩坑。

## 七、提 PR 后会发生什么

1. 作者看你的 PR
2. 可能会问几个问题、或请你调整
3. 合并到 main
4. 作者打包发版

**不要**自己在 fork 上改版本号 —— 版本号由作者统一管理（`sphdl/__init__.py`）。

## 八、几个容易踩的坑（来自 PITFALLS.md）

| 坑 | 说明 |
|---|---|
| **`git add -A` 会误提交构建产物** | 永远用显式文件列表 |
| **改 `gui.py` 后必跑 `test_sniff_smoke`** | 有 3000+ 行，patch 容易吞掉相邻语句 |
| **`.bat` 文件必须存 GBK 编码** | UTF-8 在 cmd 下会乱码报"不是内部或外部命令" |
| **`after` 定时器不能在里面再排任务** | 会指数增殖导致界面卡死 |
| **改档位名要搜全 7 处** | 见 PITFALLS #66 |
| **设备指纹采集必须后台线程** | 同步采集会让启动卡 4 秒 |
