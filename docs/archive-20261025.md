## 二、核心变更

### 2.1 视频号评论（v2.2.12 ~ v2.2.15，客户提的新功能）

| 能力 | 说明 |
|---|---|
| 自动抓取 | 在微信里点开视频评论区翻页，评论自动进清单（不用下载视频） |
| **嵌套回复** | 粉丝互相对答按层级保存，界面缩进 + 竖线，对齐视频号 |
| 查看 | 工具栏「💬 查看评论」/ 右键菜单，窗口样式对齐视频号 |
| 导出 | 单条导出（txt/json）+ **批量下载评论**（多选一次导出） |

**关键设计**：不依赖 `cmdName` / 固定字段名，按结构特征识别
（视频号接口会改名，写死等于写死一个会过期的功能）。

**数据结构**：
```python
Record.comments = [
  {"nick", "content", "likes", "time", "cid",
   "replies": [ ...同结构，递归... ]}
]
```

### 2.2 客户报障修复（按严重度）

| 报障 | 根因 | 严重度 |
|---|---|---|
| **抓不到任何视频** | `_pick` 重复定义覆盖原函数 → 静默返回 None | ★★★ 我引入 |
| **分享包带真实授权码** | 使用说明的「格式示例」是真码，6 个已发包含它 | ★★★ 安全事故 |
| **未授权却能下载** | addon 自动下载绕过授权门禁，漏洞存活 5 版 | ★★★ 安全漏洞 |
| 优酷/视频号都播不了 | mitmproxy 拦全系统 + IPv6 不通卡死 | ★★ |
| 换新版授权丢失 | 配置存 exe 目录，换目录=全新安装 | ★★ |
| 部分视频抓不到评论 | 拦截白名单只 9 条，评论接口在别的子域 | ★★ |
| 评论数 24 vs 69 | 只取最大列表，嵌套回复全丢 | ★★ |
| 启动崩溃 | `records.json` 当 dict 用 | ★★ 我引入 |
| 停止所有下载没停住 | 按 URL 取消，没清 pipeline 队列 | ★ |
| 大小显示 183M 实际 18M | 显示的是元数据最高画质值 | ★ |
| 解析没反馈 | 只有底部小灰字 | 体验 |
| 找不到回清单入口 | 提示里的按钮不存在 | 体验 |

### 2.3 新增防护

| 防护 | 作用 |
|---|---|
| `verify_no_duplicate_helpers.py` | 扫所有模块函数名，禁止重名（防 `_pick` 类事故） |
| `diag_capture_chain.py` | 抓不到视频时 30 秒定位断在哪一段 |
| `verify_zip_clean_for_new_pc.py` | 模拟另一台电脑，确认包内无本机数据 |
| 打包自检（`release.py`） | 扫包内授权码/config/records，命中直接报错退出 |
| 发版自动同步 CHANGELOG | 后台「更新要点」不再靠手工 scp |
