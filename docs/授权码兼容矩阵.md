# 授权码兼容矩阵（向前兼容判据）

> 目的：每次动产品表（`license.py` 的 `PRODUCT_*` / `PRODUCTS_NO_TIER` /
> `FLAG_ALL`）后，用这张表 + `tests/verify_v347_compat.py` 确认
> **以前发出去的码全部照旧可用**。
> 最后更新：2026-11-14（v3.4.6 加第 6 条产品线「小程序短剧/绿泡泡」后复核）

## 码型一览（靠首字节 ver 分流，互不影响）

| ver | 长度 | 载荷 | 用途 | 客户端解析 |
|---|---|---|---|---|
| 1 | 35 字符 | ver/tier/days/rand | 最老的码，**只有视频号** | product 隐含 = 1 |
| 2 | 38 字符 | + product | 分产品线（公众号/抖音/B站/小鹅通/绿泡泡） | product 直读 |
| 3 | 46 字符 | + dev4 | 死绑单机 | device_bound=True |
| 4 | 40 字符 | + maxdev | 限台数（0=不限） | max_devices / device_limited |
| 5 | 43 字符 | + caps | 视频号 + 增值能力位（点赞增强包） | caps 位判断 |

## 新增产品线时必须同步的 6 处

客户端 3 处、发码后台 3 处，缺一处就是「发出来客户端不认」或「后台选不到」：

1. `sphdl/license.py`：`PRODUCT_X = n`、`PRODUCT_LABELS`、`FLAG_X`
2. `sphdl/license.py`：`PRODUCTS_NO_TIER`（不分档产品必须加，否则按视频号查档位直接抛错）
3. `sphdl/license.py`：`label_of_product()` 的展示分支（可选但建议）
4. `server/sphdl_admin.py`：`PRODUCT_X = n`、`PRODUCT_LABEL`、`NO_TIER_LABEL`
5. `server/sphdl_admin.py`：`PRODUCTS_NO_TIER`
6. `server/sphdl_admin.py`：发码页 `<option value="n">` + 复制话术前缀

## 回归方法

```bash
# 算法层：五种码型生成→校验
python tests/verify_v347_compat.py

# 真实台账：把 VPS 上的台账拉下来，逐条校验（不提交进仓库）
ssh vps-aliyun "sudo cat /opt/sphdl-admin/data/licenses.jsonl" > /tmp/licenses.jsonl
SPHDL_LEDGER=/tmp/licenses.jsonl python tests/verify_v347_compat.py
```

判据（2026-11-14 实测）：台账 **69 枚**历史码（ver 2/3/4/5）**全部校验通过**，
字段与台账一致；`verify_v347_compat.py` **35 项全绿**。

## 两个容易忘的点

- **`_lic_key.py` 是构建期注入、发版后会被 `release.py` 删掉**。
  本地跑兼容校验前先 `python tools/license_tool.py init`（或从 `.license_secret`
  重新生成），否则 `verify_code()` 一律返回 None，看起来像"所有老码都失效"。
- **老码不会自动获得新增产品线**。比如 v3.4.6 起「小程序短剧」是第 6 条产品，
  只有视频号老码的客户升级后该功能会停止落盘——这是商业口径变更的必然结果，
  贴一枚绿泡泡码即可恢复，其它功能不受影响。
