# sphdl 桌面 GUI —— 需求文档（补齐版）

> 状态：已实现（2026-08-24）。实现映射见第 7 节。
> 技术选型：**tkinter（Python 标准库，零新增依赖）** + 现有 sphdl 核心模块。
> 不做 Web 前端 / Electron —— 目标是"双击 run.bat 就有窗口"，越轻越好。

---

## 1. 背景与目标

CLI 版对非技术用户有三个痛点：
1. 黑窗口里日志滚动，用户不知道"现在能不能下了"；
2. 下载结果只在日志里，没有可点选的文件列表；
3. 失败（如 CA 证书没装）要读英文报错才能定位。

GUI 目标：**让"启动嗅探 → 播视频 → 得到 mp4"变成三个按钮的事**，
失败时给出**中文、可操作**的提示。

## 2. 使用场景

| 场景 | 用户动作 | 系统行为 |
|---|---|---|
| 首次使用 | 双击 run.bat | 弹出主窗口；检测到 CA 未安装则红色警示 + 一键打开证书向导 |
| 日常下载 | 点「启动嗅探」→ 微信里播视频 | 列表实时出现新记录：等待→下载中 xx%→解密中→已完成 ✓ |
| 下载失败 | 双击失败行 | 弹出中文失败原因；点「重试」重新入队 |
| 收尾 | 点「打开文件夹」/ 双击已完成行 | 用系统默认程序播放 mp4 |
| 退出 | 点窗口 ✕ | 若引擎在跑，确认→停止引擎→恢复系统代理→保存列表与配置 |

## 3. 功能需求

### F1 嗅探引擎控制
- F1.1 一键 启动 / 停止 本地代理（mitmproxy，默认 127.0.0.1:8899）。
- F1.2 端口可改（1–65535 校验）；引擎运行中禁止改端口。
- F1.3 「自动设置系统代理」复选框（默认开）；停止时**无论成败都要尝试恢复**。
- F1.4 启动后轮询端口真实监听（≤5s），区分"已监听"与"启动失败"。
- F1.5 启动失败（端口占用等）给出明确日志与状态栏提示，不残留半开状态。

### F2 CA 证书
- F2.1 启动时后台检测 用户/本机 受信任根存储中的 mitmproxy CA（只读查询）。
- F2.2 状态展示：已安装 ✓ / 未安装 ⚠ / 未知 ?（检测超时不阻塞 UI）。
- F2.3 「安装/检测」按钮：唤起 `install-cert.bat`（Windows 证书导入向导，
  当前用户存储，无需管理员），同时刷新一次检测。
- F2.4 未安装时点「启动嗅探」→ 强提示（HTTPS 解不开），可选择"仍要启动"。

### F3 下载目录
- F3.1 展示当前目录；「更改…」用系统目录选择器。
- F3.2 「打开文件夹」直接资源管理器打开。
- F3.3 更改后**立即生效**（新任务写入新目录）并持久化到 config.json。

### F4 下载列表（核心）
- F4.1 列：状态 / 标题 / 大小 / 来源（JS回调、API直嗅(host)）/ 时间 / 文件名。
- F4.2 状态机：等待 → 下载中 xx% → 解密中 → 已完成 ✓ / 失败 ✗；
  颜色区分（绿/红/蓝/橙/灰）；下载进度实时刷新（300ms 轮询）。
- F4.3 行操作：
  - **重试**：重建 VideoData 重新入队（引擎停止时也可用——管线独立于代理）；
  - **打开文件 / 打开文件夹**：os.startfile；
  - **删除记录**（保留文件）/ **删除文件+记录**（二次确认）；
  - **清空已完成**（批量，保留文件，二次确认）。
- F4.4 双击行：已完成→播放；失败→弹原因。
- F4.5 **持久化** records.json（v2.0.17 起档位 4 档：轻量版 500 / 标准版 1000 / 专业版 2000 / 旗舰版 2 万条，**由授权码解锁、客户端不可自配**；满档停止加载后续视频，删记录后可继续加载；换码立即生效无需重启）：重启不丢列表；
  重启时把上次未完成的记录标记为"已中断（程序重启）"失败态，可重试
  （重试依赖记录中保存的 url + decode_key）。

### F5 日志区
- F5.1 实时显示核心模块日志（logger.subscribe 钩子，线程安全队列投递）。
- F5.2 分级着色（info 蓝 / ok 绿 / warn 黄 / error 红）。
- F5.3 自动滚动（可关）；「清空」；超长自动裁剪（保留最近 1000 行）。

### F6 状态栏
- 一行汇总：嗅探状态(端口) | 系统代理状态 | CA 状态 | 列表统计(共/完成/失败)。

## 4. 交互与线程需求

- N1 **绝不跨线程碰 tkinter**：mitmproxy 线程 / Pipeline 工作线程的回调
  一律 `queue.Queue` 投递，主线程 300ms 轮询消费。
- N2 引擎启停、CA 检测、证书向导唤起都在工作线程，UI 不卡死。
- N3 退出时按序：停引擎（≤6s join）→ 恢复系统代理 → 存 config/records → 销毁窗口。
- N4 引擎崩溃/异常退出：日志红字 + 状态栏回到"已停止"，窗口不崩。
- N5 窗口最小 900×560，默认 1060×700；中文字体（微软雅黑 UI）优先。

## 5. 数据文件（都在工具目录 sphdl/ 下）

| 文件 | 内容 | 写入时机 |
|---|---|---|
| config.json | port / download_dir / auto_proxy | 改动即存 + 退出时 |
| records.json | 下载记录列表（含 url+decode_key，供重试） | 有变更时（轮询内去抖）+ 退出时 |

## 6. 非功能需求

- 零新增第三方依赖（tkinter 随 Python 发行）；
- GUI 启动 < 3s（CA 检测异步，不阻塞首屏）；
- 空转时 CPU 占用 ≈ 0（300ms 轮询 + 无流量时管线空闲）；
- 所有用户可见文案为中文。

## 7. 实现映射

| 需求 | 代码位置 |
|---|---|
| F1 | `sphdl/gui.py` → `SniffEngine.start/stop`、`_toggle_engine` |
| F2 | `sphdl/gui.py` → `_check_ca`（PowerShell 只读查询）、`_launch_cert_wizard`（install-cert.bat） |
| F3 | `sphdl/gui.py` → `_choose_dir` / `_open_download_dir` + `AppConfig` |
| F4 | `sphdl/gui.py` → `RecordStore`、Treeview 区、`_retry` 等 |
| F5 | `sphdl/gui.py` → `_append_log`；`sphdl/logger.py` → `Logger.subscribe` |
| F6 | `sphdl/gui.py` → `_update_status_bar` |
| N1 | `App.push_event / push_log / _poll`（queue 模型） |
| 事件钩子 | `sphdl/pipeline.py` → `on_event`（start/progress/decrypting/done/failed）；`sphdl/addon.py` → `on_capture` |
| 进度回调 | `sphdl/downloader.py` → `download_file(..., progress_callback)` |
| 入口 | `main.py --gui`；`run.bat` 无参数默认进 GUI，带参数透传 CLI |

## 8. 已知限制 / 后续可做

- 列表"来源"不区分手动粘贴（GUI 无手动粘贴入口，CLI 才有）；
- 下载进度基于 Content-Length，服务端不给长度时只显示"下载中"无百分比；
- 无多实例：同一端口只允许一个引擎（再开会提示端口占用）；
- 可加：右键菜单、按标题搜索、下载完成声音提示、托盘最小化。
