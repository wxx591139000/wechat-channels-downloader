## 3. 本轮核心技术突破

### 3.1 抖音主页批量抓取：为什么工具自己请求不行

**全部实测否定**：

| 方式 | 结果 |
|---|---|
| 工具 `fetch` 翻页 | 第 1 页 18 条，第 2 页起返回 0（限流） |
| headless 滚 `scrollTop` | 只拿到第 1 页 |
| 分步滚动 | 反复请求第 1 页，cursor 不前进 |
| 先等 8 秒再滚 | 偶发成功，不可复现 |
| 传完整 aweme 对象（1.8MB）| 序列化耗时 → 第 2 页被限流 |

**关键洞察**：抖音对「页面自己发的请求」放行，对「工具主动发的请求」限流。

**最终方案**：客户在可见浏览器里滚动 → 页面自己发请求 → 工具 `on("response")` 监听。

**实测**：
```
滚 1 次 → 18 条 (cursor 1786593802000)
滚 2 次 → 36 条 (cursor 1778817648000)
滚 3 次 → 54 条 (cursor 1767605400000)
滚 4 次 → 84 条 (has_more=0)
总耗时 22.5 秒
```

### 3.2 小程序短剧：连播抓取

客户澄清「一集播完会自动跳下一集」→ 实测确认（02→03 间隔 60 秒 = 一集时长）。

**所以「批量」已经实现了**：打开短剧 → 播第一集 → 工具挂着自动存。

## 4. ★★★ 三个最贵的教训

### 4.1 `except Exception: pass` 吞掉配置型代码的致命错误

```python
try:
    st.configure("Primary.TButton", ..., font=(FONT, 10, "bold"))
    #                                    ^^^^ FONT 不存在
except Exception:
    pass          # ← NameError 被吞，整个样式块从未执行
```

**后果**：所有按钮配色失效（包括原有的公众号/抖音样式）。
界面看起来"只是不好看"，实际是配置全丢。

**客户报障时的表现**：「抖音按钮文字看不见」——看起来像小问题，实际是配置崩溃。

**修法**：配置型代码的 `except` 必须 `logger.warn`，不能 `pass`。

### 4.2 PyInstaller 不加 `--clean` → 打包出旧代码

**v2.9.6 和 v2.9.7 两个版本完全废掉**，客户双击直接崩：
```
AttributeError: 'App' object has no attribute 'tree'
```

根因：`release.py` 没加 `--clean`，复用了 `~/.pyinstaller` 缓存 + 残留 `.pyc`。

**铁律**：
1. 打包必须 `--clean` + 清 `__pycache__`
2. 打包后**必须真的运行 exe 并确认窗口出现**（`--selftest` 不启动 GUI）

### 4.3 Windows Tk 截图：`ImageGrab` 截不到窗口内容

验证「日志区是否显示」时，`ImageGrab.grab(bbox=窗口区域)` 截出来
**完全没有 Tk 控件内容**。

害我：
- 三种布局（pack 双 expand / side=bottom / grid weight）全判为"失败"
- 白改两版布局
- 实际都能正常显示

**正确方法**：Win32 `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT=2)`。

**注意**：找窗口按面积排序取最大，否则抓到 tooltip（实测抓到过 314×50）。
