## ③ 设备绑定校验（v2.0.19）

### 机制

```
发码时：把客户的设备码写进授权码（ver=3 码型）
启动时：客户端算本机设备码 → 与授权码里的比对
  一致 → 正常使用
  不一致 → 提示"授权不属于本机"，可切到未授权默认档
```

### 客户流程（比之前多一步）

1. 客户收到软件，打开 → 点「🔑 授权管理」→ 看到「本机设备码」如 `4770-0AEB-18B6-1AB4`
2. 把设备码发给你
3. 你用设备码生成绑定码：`gen 20000 --device 4770-0AEB-18B6-1AB4`
4. 客户粘码 → 校验通过

### 兼容性（重要）

- **ver=1 / ver=2 老码不绑设备**，继续有效（已发出的码不受影响）
- ver=3 才绑设备 → 你决定哪些客户用绑定版
- 绑定版客户换机 → 重新发一个绑定新设备码的码（台账留记录）

### 已知限制

- 会读硬件标识的人能伪造（需改代码，门槛较高）
- 客户换硬件（主板/硬盘）可能导致设备码变 → 需换码，售后成本上升
- 因此**建议只对高价档（专业版/旗舰版）启用**

## ④ 上报 + 台账

### 上报（客户端 → VPS）

- 开关：`sphdl/config.py` 的 `TELEMETRY_ENABLED`（当前 **True**）
- 时机：**仅激活时一次**，之后全程静默
- 内容：授权码哈希 + 设备码哈希 + 版本 + 时间 + /24 网段
- 失败静默丢弃，不影响任何功能

### 台账（本机）

- 位置：`E:\myHermesWorkSpace\_archives\keys\licenses.jsonl`（仓库外，含客户 PII）
- 发码时自动登记；可手工补录

### 追踪报告

```bash
# 1. 建 SSH 隧道（★只用隧道，不走公网）
ssh -f -N -L 3010:127.0.0.1:3010 vps-aliyun

# 2. 出报告
cd E:/myHermesWorkSpace/wechat-channels-downloader/sphdl
python tools/license_tool.py ledger track --vps http://127.0.0.1:3010
```

报告三段：
- **① 一码多机** = 强转卖信号（带客户信息，直接找到是谁）
- **② 一机多码** = 有人在收集码
- **③ 已发出未激活** = 还没用的码

### ★ 为什么只走 SSH 隧道

`license.zhuanlu.xyz` 走 Cloudflare，CF 的 Browser Integrity Check 会拦非浏览器
UA（返回 `403 error code: 1010`，请求根本到不了 VPS）。两条路：

- ❌ 在 CF 后台加 WAF 跳过规则 → 等于把管理接口暴露在公网，只靠一个令牌保护
- ✅ **只走 SSH 隧道** → 管理接口只监听 127.0.0.1，公网完全不可达

选后者。令牌存 `~/.sphdl_admin_token`。

## 不建议做的

- **联网激活/心跳**：与"便携离线"定位冲突，服务器挂了客户全废
- **给每个客户单独打包 exe**：分发必须同一个包，差异只在授权码里
