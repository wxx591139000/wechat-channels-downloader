## 二、v2.1.6 → v2.1.8 修了什么

| 版本 | 报障原话 | 真实原因 |
|---|---|---|
| **v2.1.6** | 「开着批量拉取，授权 500→1000 后批量被关了，抓取还卡在 500」 | **不是授权动了批量** —— 满档先自动停了批量，升档后没恢复 |
| **v2.1.7** | 「默认行数改 0，只有授权后才能下载」 | 改成「可捕获可预览、**不能下载**」；0 的语义是"不限捕获"不是"禁止捕获" |
| **v2.1.8** | 「在 2.1.5 做完授权，重启软件后授权丢失了」 | **不是授权失效** —— `config.json` 损坏/被杀软删 → 静默回默认档，**旧版零提示** |

### v2.1.8 的修法（三处配合，缺一不可）

```
save() 成功   → copy2(config.json → config.json.bak)
_load() 失败  → 三分支：FileNotFoundError / JSON 异常 / 双坏
                每条都写 _config_load_error
App.__init__  → 有值就 push_log + root.after(600, 弹窗)
                弹窗必写「同一个授权码可以重复激活，不会失效」
```

**为什么必须弹窗**：客户看到"授权没了"只会以为码废了/软件坏了，
实际是配置文件被删。**不解释 = 客户的信任损失。**

## 四、★仓库开源（本次重大变化）

| 项 | 变化 |
|---|---|
| 可见性 | PRIVATE → **PUBLIC** |
| 协作模式 | 单人 → **Fork + PR**（有朋友加入维护） |
| `.git` 体积 | 545 MB → **636 KB**（-99.9%） |
| 协作者 clone | 62 MB → **1.6 MB** |

### 为什么必须清历史才能公开

历史里有 5 个 30MB 的 v1.0~v1.2 exe 包 —— **那是 8 月还没有授权码体系的版本，
下载即用、无任何限制**。公开 = 任何人 clone 就能拿无限免费版。

清理用 `git filter-repo --path dist/ --invert-paths`，同时拔掉 `.gitignore` 里
最后一条通配例外 `!dist/微信视频号下载器-v1.2-...zip`
—— **那正是 2026-10-16「`git add -A` 误提交 17 个 zip / 540MB」事故的根因规则。**

### 公开安全的前提

**密钥靠架构保护，不靠私有仓库**：`sphdl/_lic_key.py` 是构建期注入、不入库。
所以别人拿到源码**也造不出授权码**（有测试 `verify_max_records.py` B5 段专门验证）。

### 公开踩的两个坑

| 坑 | 表现 | 定位方法 |
|---|---|---|
| **可见性静默回退** | force push 后，仓库主页/tag/Release **全部 404**，但 `gh release view` 正常显示附件 | `gh api repos/<o>/<r> --jq '.visibility'` —— **URL 404 先测主页** |
| `gh release create <tag> <file>` 静默失败 | `state=uploaded` 但下载 404 | 分两步走 API；判据看 `size` 是否等于本地字节数 |

### 三份文档的核心判据（写文档时必须保留）

- **问题一**：点「安装/检测」弹黑窗写"找不到 CA 证书文件" = 跳过了「先启动嗅探」
- **问题二**：`inetcpl.cpl` → 局域网设置 → 看代理指向 8899（本工具）还是别的端口
- **问题三**：看日志「流活动」
  - `流活动 无` → 流量没走代理（走问题二）
  - `流活动 3秒前` + `页面注入 0 次` → 接管失败（关页面重进）
  - `流活动 3秒前` + `页面注入 5 次` + `捕获 0` → 接管了没识别到（可能图片帖）
