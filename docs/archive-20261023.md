## 二、核心设计

### 2.1 去重键必须是 `(ver, channel)`

**实测踩到的真实问题**：先存百度 v2.2.2，再存夸克 v2.2.2 → **百度那条被覆盖了**。

用户两个网盘都在用（不同客户偏好不同），所以：

| 操作 | 结果 |
|---|---|
| 同版本 + 不同网盘 | **并存**（各一份） |
| 同版本 + 同网盘 | 覆盖（更新链接用） |

`channel_of(link)` 按域名识别：

```
pan.quark.cn → 夸克    baidu.com → 百度    drive.uc.cn → UC
aliyundrive|alipan → 阿里    115.com → 115    其他 → 兜底
```

### 2.2 粘贴即解析，做双份

```
用户粘贴网盘分享文字
   ├─ 前端 JS_PASTE.autoParse()   → 即时填 4 栏 + 提示「✅ 已识别：版本 2.2.2 · 文件名 · 链接 · 提取码 xsSS」
   └─ 服务端 parse_share_text()   → 前端没填全时兜底再解析一次
```

**实测**：只提交那两行原文（字段 `raw`），四个字段全自动入库。

### 2.3 解析规则要点

| 字段 | 规则 |
|---|---|
| 文件名 | 夸克`「」` → 百度`通过网盘分享的文件：` → 任意安装包名（三档兜底） |
| 链接 | 只认 `https?://` → **天然避开夸克伪链接行 `/~f3fa3bgctl~:/`** |
| 链接清理 | 必须剥掉尾部粘连中文（`?pwd=xsSS提取码`） |
| 提取码 | 先 `[?&]pwd=`，再 `提取码[:：]xxxx` |
| 版本号 | 从文件名抽 `[vV](\d+(?:\.\d+){1,3})` |

## 三、修掉的 5 个坑（都实测确认）

| # | 坑 | 修法 |
|---|---|---|
| 1 | **按 ver 去重 → 夸克覆盖百度** | 去重键改 `(ver, channel)` |
| 2 | **JS 大括号与 f-string 冲突** → `SyntaxError` | 脚本抽独立常量 `JS_PASTE` |
| 3 | **raw string 里 `\\s` ≠ `\s`** → 正则全废 | JS 写 `\s`；断言无双反斜杠 |
| 4 | **f-string 表达式不能有反斜杠** | 先算成变量再 `+` 拼接 |
| 5 | **clipboard 在 http 下不可用** | `execCommand('copy')` 兜底 |
