# 项目目标 SPEC — 微信视频号下载器 (sphdl)

> 归档日期：2026-10-17 ｜ 当前版本：**v2.1.8** ｜ 状态：✅ 已发布（含完整授权+防盗体系）
>
> **防盗体系完整方案见 `防盗体系-VPS完整方案.md`**（四层防护 + VPS 部署 + 运营动作）
> **档位（v2.1.8 改名）**：轻量(500) / 标准(1000) / 旗舰(2000) / 至尊(20000)

## 1. 项目定位与目标

一键下载微信「视频号」加密视频，并自动解密为可播放的 MP4（Windows 10/11）。

视频号视频文件**前 131072 字节（128KB）被 XOR 加密**，密钥流由服务端下发的
`decode_key` 经 Isaac64 PRNG 生成；128KB 之后是明文。工具链 =
**捕获 (url + decode_key) → 下载加密文件 → Isaac64 解密前 128KB → 保存 MP4**。

目标用户：想在 Windows 上把 PC 微信视频号里自己有权访问的视频备份下来的人，
无需 Python 环境（免安装便携版）。

**非目标（边界）**：
- 不做批量/多账号抓取、不做定时任务（有风控与合规风险，明确不做）
- 不做 macOS/Linux（依赖 Windows 系统代理注册表 + tkinter，单平台）
- 不做 Web 前端 / Electron（坚持 tkinter，双击 run.bat 出窗口，越轻越好）

## 1.5 产品与授权模型（v2.1.8）

### 两个产品线（互斥，一个码只解锁一条）

| 产品 | 档位 | 说明 |
|---|---|---|
| 视频号下载 | 轻量 500 / 标准 1000 / 旗舰 2000 / 至尊 20000 | 嗅探+解密，列表容量按档位限制 |
| 公众号文章视频 | 不分档（tier=0） | 解析 mp.weixin.qq.com 文章，明文 MP4 直链 |

### 四种授权码型（并存）

| 码型 | 长度 | 语义 |
|---|---|---|
| ver=1 | 35 | 老码，仅视频号，不绑机不限台 |
| ver=2 | 38 | 含产品线，不绑机不限台 |
| ver=3 | 45 | **死绑单机**（4 项取 2，抗硬件变动） |
| ver=4 | 40 | **限 N 台**（服务器统计执行） |

### 档位约束

- **客户端不可自配**：界面无档位下拉，客户改 config.json 也改不了
- 档位来源优先级：构建预置 → 有效授权码 tier → 默认 500
- 已发出的老码永远有效（码里存 tier 数字，改名不影响）

### 防盗边界（诚实声明）

- 能防：普通转卖、随手分享给朋友
- 防不住：逆向破解、断网绕过台数校验
- 边界详见 `防盗体系-VPS完整方案.md` §八

## 3. 技术栈与架构概览

- **语言/运行时**：Python 3.10+（开发版）；PyInstaller 6.2 冻结为 win64 便携版
- **GUI**：tkinter（标准库，零新增依赖）
- **代理/嗅探**：mitmproxy 11（进程内 API：`mitmproxy.master.Master` + addon）
- **下载**：requests（单连接 + Range）
- **解密**：纯 Python Isaac64（RandCtx64/mix/is_aac64）
- **系统代理**：Windows 注册表 `HKCU\...\Internet Settings`（set/restore）
- **打包**：PyInstaller spec（onedir，`_internal/` 布局）
- 依赖全集见 `sphdl/requirements.txt`（mitmproxy 11 + requests + Brotli）

模块划分见 `ARCHITECTURE.md`；捕获原理（bridge 钩子 + API 直嗅）见 `sphdl/README.md`。

| 组件 | 位置 | 接口/职责 |
|------|------|-----------|

| 插件 | `sphdl/sphdl/addon.py` | mitmproxy addon：bridge 钩子注入（`</head>` 前注入 invoke 包装器）+ `__sphdl/bridge` 回传截获 + API 直嗅 |
| 解析 | `sphdl/sphdl/parser.py` | object_desc 解析，snake/camel 双兼容，提取 media[] (url, decode_key, size, video_id) |
| 下载 | `sphdl/sphdl/downloader.py` | 单连接顺序下载 + 断点续传 + 微信 UA + 停止信号 |
| 解密 | `sphdl/sphdl/decryptor.py` | Isaac64 前 128KB XOR 解密 + ftyp 校验 |
| 管线 | `sphdl/sphdl/pipeline.py` | 下载任务队列（工作线程） |
| 代理管理 | `sphdl/sphdl/proxy_manager.py` | 系统代理设置/恢复 + mitmproxy CA 证书检测 |
| 实体/配置/日志 | `sphdl/sphdl/entities.py / config.py / logger.py / shared.py` | VideoData 实体、路径常量（冻结感知）、**档位定义（`MAX_RECORDS_TIERS/NAMES/LABELS`，单一事实源）**、日志落盘、同进程 UA 共享 |
| 授权 | `sphdl/sphdl/license.py` | 授权码生成/校验（HMAC-SHA256 截断、base32 去混淆字母表、容忍 O→0/I→1）、档位编码 `1=500/2=1000/3=2000/4=20000`、有效期（自首次激活起算）、`selftest()` |

| 构建期密钥 | `.license_secret` → `sphdl/_lic_key.py` | `.license_secret`（32B hex，不入库）→ 构建时混淆注入 `_lic_key.py`（不入库，构建后清理）；缺密钥则任何码无效 |
| 共享端点 | `127.0.0.1:8899/__sphdl/bridge` | 注入 JS POST 的落点（addon request() 截获 + flow.response 短路） |

## 5. 已知约束与边界

1. **仅 Windows**（系统代理走注册表；tkinter 可用）
2. **微信版本更新**可能改变 objectDesc 结构 / IPC 通道（WeixinJSBridge.invoke
   "finderH5ExtTransfer"），需跟进
3. **引擎启动前已打开的视频号页面没有 bridge 钩子** → 须重新进入视频号或重启微信再播放
4. **CDN 链接带时效 token** → 隔太久「重新下载」可能失败，需重新嗅探
5. **Chromium 缓存死代理**：引擎停止后微信/浏览器可能缓存 8899 死代理，需完全重启
6. **部分视频走纯本地缓存**（无任何网络请求）→ 无法捕获
7. **限速**：CDN 单连接限速（约 400KB 一掐），10MB 视频约 2-5 分钟，属上游限制
8. **合规**：仅供个人学习研究 + 备份自己有权访问的内容；禁止商业用途/批量抓取
9. **容量上限（v2.0.17 实测）**：旗舰版 20000 条为经压测的容量上限——
   2 万条插入 0.12s / 落盘 1.14s / records.json 12.9MB / 内存 +18MB / 启动 0.29s / 排序 1.83s；
   3 万条起「点表头排序」明显变慢（5.74s），5 万条 38s 不可用。故不上更大档位。
   （排序性能优化列入后续版本，不在 v2.0.17 范围）
10. **授权码安全边界（如实交代）**：PyInstaller 打包的 Python 字节码，反编译后可直接
    改档位判定。能挡「改配置 / 猜码 / 抄码 / 换机重装」，挡不住愿意逆向的人。
    要更强需把档位判定下沉到原生层（当前不划算）。
11. **授权码不绑定设备**：一码可在任意机器使用（换机重装重新粘一次即可）；
    如需限制扩散需另加机器指纹方案（未实现，v2.0.17 决策为不绑）。
12. **`.license_secret` 是关键资产**：丢失后已发出的授权码在**新构建**里全部失效
    （旧包不受影响）；须备份到密码管理器。


### 1.6 未授权策略（v2.1.8 定稿）

| 能力 | 未授权 | 已授权 |
|---|---|---|
| 捕获视频、查看列表 | ✅ 可以（上限 500 条） | ✅ 可以（按档位） |
| 下载视频文件 | ❌ **不可以**（点下载弹窗引导激活） | ✅ 可以 |
| 公众号视频解析 | ❌ 需公众号授权码 | ✅ 可以 |

**设计理由**：让客户先完整看到"这工具确实能把视频全抓下来"，
再决定购买。比"未授权什么都抓不到"成交率高得多。

**实现约束**：
- `config.DEFAULT_MAX_RECORDS = 0`，其中 0 的语义是**不限制捕获**（非"禁止捕获"）
- 但未授权时按 `config.UNLICENSED_CAPTURE_LIMIT = 500` 封顶
  （完全不限会让客户抓几万条，排序 5 万条要 38 秒 → 界面卡死，见 PITFALLS #7）
- 下载门禁放在 `_submit_record()` —— **所有下载路径的唯一出口**
  （手动选中 / 全部待下载 / 自动下载 / 重新下载 / 重试失败）

## 1.7 清单交互（v2.1.9 ~ v2.2.2）

### 序号列（两个概念必须分开）

| | 含义 | 会变吗 |
|---|---|---|
| **序号列（显示）** | 当前列表第几个，1..N 连续 | 排序/筛选/删记录后**重编** |
| **seq（内部字段）** | 抓取先后顺序 | **永不改变**（删记录也不复用） |

点「序号」表头 = 按 `seq` 排序 = 还原「在视频号里刷到的顺序」。

**各场景定稿行为**：

| 场景 | seq | 序号列 |
|---|---|---|
| 删部分记录 | 继续递增，留空档（1,3,5） | 重排 1,2,3（客户看不到空档） |
| 清空全部（不重启） | **重置为 1** | 从 1 开始 |
| 清空全部（重启） | 从 1 开始 | 从 1 开始 |
| 删除后重启 | 从 max(现存)+1 继续 | 连续 |

### 多选操作（客户反馈"不知道怎么多选"）

列表下方常驻蓝色提示条（**不是 tooltip** —— 客户不会去悬停找说明）：

```
💡 多选技巧  点一行＝选中一个 │ 按住 Ctrl 再点＝逐个加选 │
   按住 Shift 再点＝连续选一段 │ Ctrl+A＝全选 │
   「反选」＝选中的变不选、没选的变选中
   点「序号」表头＝按抓取先后排序
```

配「全选」「反选」两个可见按钮（不用记快捷键）。

### 停止嗅探与下载的关系（v2.2.0）

**下载走系统代理**（`requests` 的 `trust_env=True` → 经 mitmproxy），
所以「停止嗅探」会断开下载通道。

- 停嗅探前先检查下载任务，有则弹窗三选一：
  【是】等它们下完自动停 / 【否】立刻停（保留断点）/ 【取消】不停
- 失败时**保留 `.tmp`**（用户主动停的不保留），下次可 Range 续传
- 启动时清理 7 天以上未用的 `.tmp`

## 1.8 发码后台「话术库」（2026-10-21/23）

**痛点**：客户下单后要手工拼「套路词 + 对应版本网盘链接」，再粘一次授权码，
容易贴错版本、漏提取码。

### 能力

| 能力 | 说明 |
|---|---|
| 套路词 | 全局一份，改一处全生效 |
| 版本库 | 每个版本一条（文件名/链接/提取码），可增删改 |
| **多网盘并存** | **同版本可在百度/夸克各存一份，去重键 `(ver, channel)`** |
| **粘贴即解析** | 网盘分享文字整段粘进去 → 4 字段自动填 |
| 一键复制 | 「复制话术+授权码」（全套）/「只复制话术」 |

### 支持的网盘

`pan.quark.cn`→夸克 ｜ `baidu.com`→百度 ｜ `drive.uc.cn`→UC
｜ `aliyundrive|alipan`→阿里 ｜ `115.com`→115 ｜ 其他→任意 https 兜底

### 解析规则要点

- 文件名三档兜底：夸克`「」` → 百度`通过网盘分享的文件：` → 任意安装包名
- 链接只认 `https?://` → 天然避开夸克伪链接行 `/~f3fa3bgctl~:/`
- 必须剥掉链接尾部粘连的中文（`?pwd=xsSS提取码`）
- 双份实现：`parse_share_text()` 服务端兜底 + `JS_PASTE` 前端即时反馈

## 1.9 视频号评论（v2.2.12 ~ v2.2.15）

### 能力
- **自动抓取**：在微信视频号里点开某视频评论区并翻页，评论自动进清单
  （不需要下载视频）
- **嵌套回复**：粉丝互相对答按层级保存（`replies` 字段，最多 4 层）
- **查看**：工具栏「💬 查看评论」/ 右键菜单，窗口样式对齐视频号
- **导出**：单条导出（txt/json）+ **批量下载评论**（多选后一次导出）

### 数据结构（Record.comments）
```python
[{ "nick": str, "content": str, "likes": int,
   "time": str, "cid": str,
   "replies": [ ...同结构，递归... ] }]
```
配套字段：`comment_count`（视频号口径总数）、`comments_updated`

### 抓取策略
- 只看**结构特征**（昵称类键 + 内容类键），**不依赖 cmdName / 固定字段名**
  —— 视频号接口会改名，写死等于写死一个会过期的功能
- 只把**最浅一层**评论列表当根，更深的挂到父评论 `replies`
  （否则粉丝对答会被当独立列表丢掉 —— 实测 24 vs 69 的真因）
- 按 `cid` 或 `昵称+内容` 去重，重复翻评论不会重复追加

### 保存形式
| 形式 | 位置 | 用途 |
|---|---|---|
| 主存储 | `%LOCALAPPDATA%\sphdl\records.json` 的 `comments` 字段 | 随清单持久化 |
| txt 导出 | `<下载目录>/评论/<标题>_评论.txt` | 给人看，回复用 `└` 缩进 |
| json 导出 | `<下载目录>/评论/<标题>_评论.json` | 给程序用，完整嵌套树 |

### 已知限制
- 只能抓到「你在微信里实际翻到过」的评论；不翻到底就抓不全
- 顶部会显示「69 条评论（已捕获 24 条，翻评论区可继续抓）」
- 提取器按结构推断实现，**尚未用真实评论 payload 校准**；
  若字段名差异过大可能抓不到（有 `开启原始数据记录.txt` 诊断通道可取样）

## 1.10 大小显示口径（v2.2.14）

| 状态 | 显示 | 含义 |
|---|---|---|
| 待下载 | `≈183.00 MB` | 微信给的元数据（按最高画质算），**不是实际文件大小** |
| 已下载 | `18.00 MB` | 磁盘真实大小 |

根因：微信元数据 `size` 是最高画质值，而实际下载的是「微信当时播放的档位」，
实测可差 7 倍（198MB → 27MB）。加载旧数据时若有文件，会用磁盘大小自动修正。

## 1.11 授权码吊销（方案 B，v2.3.0/v2.3.1）

### 背景

改造前**作废对客户端完全无效**：
- `license.py` 零网络调用，`verify_code()` 纯本地 HMAC
- 授权码里只有 `tier/days/maxdev/flags/prod`，**没有"作废"字段**
- 服务器「作废」只往 `licenses.jsonl` 追加事件，**无下发通道**
- 下载门禁只读本地配置

结果：作废后客户继续下载、无任何提示，连"码被转卖到新电脑"都挡不住。

### 方案：云端吊销名单

```
服务器 GET /api/revoked  →  [{code, reason}, ...]
客户端 启动后 5 秒 + 每 30 分钟
命中 → 立即降档 + 停所有下载 + 红色大字弹窗
```

### 端点

`https://license.zhuanlu.xyz/api/revoked`
- **无需鉴权**（客户端没有后台会话）
- 直接读同机 `/opt/sphdl-admin/data/licenses.jsonl`
- 取每个码**最后一条** `voided`/`restored` 事件决定状态
- 支持 `?codes=A,B,C` 只返回关心的码
- **只返回 `code` + 通用 `reason`**，不含客户名/价格/渠道

### ★★ 客户红线：失联时绝不降档 ★★

只有**能证明**作废时才降档：

| 场景 | 降档? |
|---|---|
| 本次联网成功且明确列出该码 | ✅ |
| 断网，但 6 小时内的成功响应里明确列出该码 | ✅ |
| 404 / 500 / HTML / `ok:false` / 缺 `revoked` 字段 / 结构畸形 | ❌ |
| 连接拒绝 / 超时 / 无缓存 / 缓存过期 / 缓存损坏 / 无 verified 标记 | ❌ |
| 服务器恢复该码 | 下次校验**自动恢复档位**（可逆） |

**6 小时宽限的理由**：如果严格要求“必须实时”，客户网络抖动一次，
刚作废的码就立刻又能用，功能形同虚设。

### 客户端实现

`%LOCALAPPDATA%\sphdl\revoked_cache.json`：
```json
{"ts": 1792983647, "verified": true, "codes": {"SPHDL-...": "已作废"}}
```
`verified=true` 表示这份缓存来自一次**成功响应**，否则断网时不采信。

### 已下载文件不受影响

作废只停任务、降权限，**不删除任何已下载的 mp4**。

## 1.12 三产品线 + 增值能力位（v2.6.x，2026-10-28）

### 产品线（互斥，一个码只解锁一条）

| 产品 | product | 档位 | 说明 |
|---|---|---|---|
| 视频号下载 | 1 | 4 档（500/1000/2000/20000） | 基础产品，嗅探抓取 |
| 公众号文章视频 | 2 | 不分档 | 粘贴文章链接解析 |
| 抖音批量下载 | 3 | 不分档 | 粘贴链接批量下，Playwright 读页面 |

### 增值能力位（可叠加，与产品线正交）

| 能力 | caps | 说明 |
|---|---|---|
| 点赞增强包 | bit0 | 点赞/转发/推荐数展示 + 按点赞排序 |

**为什么不做成产品线**：产品线互斥，做成 product=4 会导致客户买了点赞就
不能再用视频号 —— 卖不出去。点赞是视频号的**增强能力**。

### 码型版本

| ver | 载荷 | 用途 |
|---|---|---|
| 1 | tier+days+rand | 老码（仅视频号） |
| 2 | +product | 带产品线，不限台数 |
| 3 | +product+dev4 | 设备绑定 |
| 4 | +product+maxdev | 限台数 |
| **5** | **+product+caps+maxdev** | **增值能力位** |

**共存规则**：靠首字节 ver 分流，老码 caps 恒为 0，完全不受影响。

### 客户可见的功能状态（授权管理页）

```
功能：视频号✓  公众号视频✗  抖音✗  点赞增强包✗
```
遍历**所有已激活的码**判定（叠加语义），未授权项可点击 → 购买引导。

## 1.9 直播回放与小程序短剧（v2.6.6 ~ v2.8.1）

### 1.9.1 直播回放

| 项 | 结论（实测） |
|---|---|
| 地址格式 | `finder.video.qq.com/.../stodownload?encfilekey=...` |
| 格式 | 完整 MP4（非 HLS），Isaac64 加密容器 |
| 单条大小 | 1.7 ~ 3.3 GB（`file_size` 真实值；元数据可能虚高 4 倍） |
| 列表一次返回 | 8 条，每条都带**完整可下载地址** |
| 抓取方式 | 滑列表即可（不需点开播放） |

**长视频整页全抓**（v2.6.6）：
```
LONG_VIDEO_SEC = 600       # ≥10 分钟算长视频
LONG_PER_PAGE_CAP = 60     # 单页最多补抓 60 条
```
先抓前 2 条（当前浏览可见），再把本页所有 ≥10 分钟的全部入列。
短视频维持 2 条，避免推荐流（一页 60 条）灌爆清单。

### 1.9.2 小程序短剧

| 项 | 结论（实测 2026-10-30） |
|---|---|
| 地址格式 | `<hash>.vodpreview.wxamedia.com/<vod>/<集号>/f0.mp4?t=...&us=...` |
| 格式 | 完整 MP4，单集 2.5 ~ 7 MB |
| 传输 | HTTP 206 + `content-range` |
| URL 时效 | `t=` 时间戳签名，**几分钟后 403** |
| 外部重下 | 微信 UA/Referer/Range/Origin **5 种组合全 403**（依赖小程序会话） |
| 切集方式 | 播放器**不能下滑**，必须点「选集」 |

**唯一可行方案：边播边存**（v2.7.7）
```
播放 → 代理拦截 wxamedia 的 mp4 响应 → 按 content-range 偏移写 .part
     → 字节区间连续覆盖即完成 → 改名
```
- 完成判定按**字节区间覆盖**，不是文件大小（乱序分片会踩坑）
- 落盘：`<下载目录>/小程序短剧/第NN集_<hash8>.mp4`
- 保存后自动入清单（来源=小程序短剧、状态=done）

**未解决（如实记录）**：
- 剧集标题 / 集数 / 整季地址列表 **没走可拦截的 HTTP**
  （诊断落盘的所有 JSON 只有埋点与心跳）
- 因此**做不到「一键下整季」**，也没有真剧名，只能按播放顺序命名
- 要拿真剧名需逆向 wxapkg 或私有协议，成功率低，暂不投入

## 1.10 授权体系（v2.6.0 起）

### 三产品线（互斥）

| product | 产品 | 特殊要求 |
|---|---|---|
| 1 | 视频号 | 需 CA 证书 |
| 2 | 公众号视频 | — |
| 3 | 抖音批量 | **不需** CA 证书 |

### 增值能力位（可叠加，不互斥）

| caps 位 | 含义 | 码型 |
|---|---|---|
| bit0 | 点赞增强包（点赞/转发/推荐展示 + 按点赞排序） | ver=5 |

**为什么不做成产品线**：产品线互斥 —— 做成 product=4 会导致
客户买了点赞就**不能用视频号**，卖不出去。

### 码型对照（★发版红线：老码必须仍有效）

| ver | 载荷 | 用途 |
|---|---|---|
| 1 | tier/days/rand/mac | 最早 |
| 2 | + product | 三产品线 |
| 3 | + dev4（设备绑定） | 单机死绑 |
| 4 | + maxdev | 限台数 |
| 5 | + caps | 增值能力位 |

**兼容性审计**：`tests/verify_license_backward_compat.py`
