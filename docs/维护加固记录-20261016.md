# 维护加固记录 · 2026-10-16

项目：微信视频号下载器（sphdl）· 执行者：Hermes CLI
主题：**列表上限档位 + 授权码**（v2.0.17）—— 根因 → 修复 → 预防 三步链

---

## 一、问题与根因（现象）

**现象**（用户报告）：底部状态栏「列表: 共 500 条 · 待下载 500」后计数不再变化，
看起来"拉到 500 条就不再加载后续视频"。

**根因**（程序化验证，非推断）：

| 编号 | 证据 | 结论 |
|---|---|---|
| R1 | `gui.py:49` `MAX_RECORDS = 500` | 列表容量硬编码，无配置入口 |
| R2 | `gui.py:230-251` `_load()` `raw[:MAX_RECORDS]` | 启动静默丢弃超出记录（数据丢失，无提示） |
| R3 | `gui.py:253-258` `add()` `pop()` 最旧记录 | 达到上限后**顶掉旧记录**且不通知 GUI → Treeview 幽灵行 |
| R4 | `gui.py:1733` 判重只看 `_url_to_rid` | 被顶掉的视频再捕获被静默判"重复"，永远回不到列表 |
| R5 | `gui.py:1727` / `gui.py:594` `any(...)` | 捕获判重 O(n)，2000/不限量档叠加成 O(n²) |
| R6 | `gui.py:1893` 每 300ms 全量直写 | 大数据量 I/O 抖动 + 非原子写，掉电可损坏整份列表 |
| R7 | 无任何满档提示 | 用户无法区分"满了"与"坏了" → 本次问题上报的直接原因 |

**行为语义定稿**（用户两次澄清）：
① 满档 = **停止加载后续视频**（不顶掉、不淘汰已有记录）；
② 不限量档要能**持续加载**；
③ 档位**不由客户配置** —— 由发布方用「授权码」或「预置版本」掌控。

## 二、修复（v2.0.17，逐项对应）

| 根因 | 修复 | 验证 |
|---|---|---|
| R1 | 4 档档位化：`config.MAX_RECORDS_TIERS`，唯一解析入口 `App._resolve_tier()`（构建预置 > 授权码 > 默认档） | C0 / C6b / C8 |
| R2 | 启动按档位保留最新 N 条 + 日志提示裁掉条数 | A6 |
| R3 | 满档改为**拒收**（`RecordStore.add()` 返回 False），不再移除任何记录；`is_full()` 用 `>=`（恰满即满） | A1 / A3b / C1 |
| R4 | 统一 `App._drop_records_ui(rec_list)` 清理 `_row_of` / `_url_to_rid` / `_vid_index`；`RecordStore` 改为返回 **Record 对象**（删了就取不回 video_id） | C2 / C5b |
| R5 | `_vid_index` 集合 + `_url_to_rid` 字典 → O(1) 判重 | 2 万条实测 0.11s |
| R6 | 落盘 3s 节流 + 原子替换（`.tmp` → `os.replace`），失败返回 False 且旧文件完好 | A4a / A4b |
| R7 | 满档提示一次（主线程事件 `("full",)`）+ 状态栏「已满·未加载 N 条」+ 自动停批量拉取 | C4 / C4b |

**新增能力（满足"档位由发布方掌控"）**：
- `sphdl/license.py` + `tools/license_tool.py`：HMAC 授权码（24 字符、含档位、可带有效期、
  离线校验、容错大小写/连字符/易混字母）。
- `release.py`：构建期从 `.license_secret` 注入混淆密钥（不入库、构建后清理）；
  `--max-records` / `--all-editions` 出预置锁档版本；`--default-records` 出试用版；
  **构建后强制 `exe --selftest-license`**。
- 界面：档位下拉**移除**，改为只读档位 + 「🔑 输入授权码」。

## 三、预防（防复发，已落地）

1. **门禁化**：`release.py` 构建后跑 `--selftest-license`，密钥没注入直接中止构建
   （防"发出去的包所有码都无效"这类静默事故）。
2. **测试固化**：`tests/verify_max_records.py` 44 项（A 段 RecordStore / B 段授权码 /
   C 段真 Tk 端到端），覆盖满档停载、无残留、升级恢复、持久化、预置锁档、
   addon 拒收回退；已纳入回归。
3. **文档固化**：PITFALLS 新增「列表容量/满档语义」6 条 + 「授权码/档位」6 条；
   本文件与 `docs/SPEC-列表上限四档.md` 记录口径与验收。
4. **密钥纪律**：`.license_secret`、`sphdl/_lic_key.py` 入 `.gitignore`；
   仓库内 `_edition.py` 永远保持"未锁档 + 默认 500"。
5. **UI 复核方式**：新增 `tests/shot_gui.py`（PrintWindow 截图，修掉 pywin32
   `PyCDC.GetBitmapBits/Detach` 不存在的老坑）+ 本地 PaddleOCR 文字复核，
   关键界面改动可留档核对（本次已识别到「列表上限：500条」「输入授权码」等）。
