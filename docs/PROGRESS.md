## 3.7 v2.1.9 ~ v2.2.2 阶段（2026-10-20，客户体验打磨）

### 起点

v2.1.8 已完成「客户报障修复」（授权丢失、未授权策略、批量恢复）。
本阶段全部来自**客户实际使用反馈**，集中在"清单交互"和"顺序"。

### 四个版本

| 版本 | 触发 | 核心改动 |
|---|---|---|
| **v2.1.9** | 客户"不知道怎么多选" | 常驻蓝色提示条 + 全选/反选按钮 + 使用说明专章 |
| **v2.2.0** | ① 客户要"下固定数量"<br>② 客户报"关嗅探后下载也停了" | ① 「序号」列<br>② 停嗅探前检查任务 + 保留断点续传 |
| **v2.2.1** | 客户"顺序要和视频号一致" | `seq` 抓取顺序 + 点序号表头排序 + 原始数据诊断开关 |
| **v2.2.2** | 用户问"删了清单序号怎么办" | 清空重置 seq，各场景行为定稿 |

### 关键决策

1. **序号列（显示）与 seq（抓取顺序）必须分离**
   - 序号列永远 1..N 连续（客户按数量选）
   - seq 永不改变（排序依据、不撞号）

2. **删部分不重置 seq，清空才重置**
   - 删部分重置会和现存撞号
   - 清空后从 1 数最直观

3. **停嗅探不能硬停**
   - 下载走系统代理（经 mitmproxy），停嗅探必断连接
   - 给客户三选一，别替他做决定

### 修掉的缺陷

| # | 缺陷 | 影响 |
|---|---|---|
| 1 | 加序号列导致双击来源列筛选静默失效 | 功能丢失且无提示 |
| 2 | 字体 bold 在 Windows 静默失效 | 提示条不够醒目 |
| 3 | 停嗅探删 `.tmp` → 已下载部分全丢 | 客户白下几百 MB |
| 4 | `_load` 白名单漏 `seq` | 重启后序号全丢 |
| 5 | 清空不重置计数器 → 序号从 101 起 | 客户以为软件坏了 |
| 6 | 测试在空数据上"全过" | 11 项断言形同虚设 |

## 3.8 发码后台运营提效阶段（2026-10-21 ~ 10-23）

### 起点

客户端 v2.2.2 已稳定，**问题从「功能」转向「卖货效率」**。
本阶段全部改动落在 `server/sphdl_admin.py`（VPS 后台），**客户端不动**。

### 三个需求（全部来自实际卖货场景）

| 需求 | 用户原话 | 落地 |
|---|---|---|
| **台账清理** | 「把测试数据都删掉，只保留人工录入的部分」 | 40 行 → 18 行，保留 14 个真实客户 |
| **话术一键复制** | 「发码时可以分别点击复制授权码 + 选择哪个版本的聊天话术」 | 话术库 + 版本下拉 + 一键复制 |
| **粘贴即解析** | 「别让我一个个填版本号，文件名，链接，提取码」 | `parse_share_text` + `JS_PASTE` |
| **多网盘** | 「也要支持夸克网盘的发货」 | 版本×渠道双维度 |

### 关键决策

1. **去重键必须是 `(ver, channel)`**
   只按 `ver` 去重 → 存夸克覆盖百度（实测踩到）

2. **解析做双份**

## 3.10 证书体验 + 授权吊销阶段（2026-10-25 ~ 10-26，v2.2.17 → v2.3.1）

### 报障 → 根因 → 修复

| 版本 | 客户报障 | 根因 | 性质 |
|---|---|---|---|
| v2.2.17 | 装 CA 证书命令窗口闪退（3 人报障，**2 人退款**） | `.bat` 是 LF 换行，cmd 解析失败 0.03s 退出 | **严重交付缺陷** |
| v2.2.18 | 「要么不显示命令窗，要么停留等待关闭」 | 批处理窗口本身就是风险源 | 设计 |
| v2.2.19 | 要求 SOP 随包 | — | 交付改进 |
| v2.2.20 | 客户纠结「下载后大小变小」 | 元数据显示最高画质值 | 产品决策 |
| v2.2.21 | 首装实测返回「操作已被用户取消」 | **写根证书库必须过 Windows 确认框**；之前只测了"已安装"短路分支 | **首装路径从未验证** |
| v2.2.22 | 提示不够醒目，「用户根本不看」 | messagebox 同字号灰字 | 体验 |
| v2.2.23 | 装完证书抓不到 | **微信启动时才读证书信任**；且静默无提示 | 设计 + 体验 |
| v2.3.0 | 「作废后用户还能下载吗」 | 客户端纯本地校验，服务器作废无下发 | **商业风险** |
| v2.3.1 | 「失联时不能降档」 | 初版 7 天缓存宽限不符合红线 | 策略收紧 |

### 本轮最重要的三个教训

**① 首装路径必须实测，不能只测「已安装」**

v2.2.17 修了 LF 后我认为搞定了，直到客户要求"我试下新版"我才删掉自己的证书去测首装，
这才发现 `certutil` 返回「操作已被用户取消」——**这个 bug 已经存在好几版，
因为每次测试都走"已安装"短路分支**。

**② 「窗口一闪而过」本身就是交付缺陷**

不管底层是换行符、杀软、UAC 还是路径问题。能用无窗口方式做的，
就不要启动控制台。最终方案是零命令行窗口 + Windows 自己的确认框。

**③ 静默失败要比报错更优先处理**

客户说的最痛的一句是「避免抓取不到，也没任何提示」。
报错至少知道怎么回事，静默失败只会让客户觉得"软件坏了"。
