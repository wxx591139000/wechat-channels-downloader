# 防盗版方案设计 — 设备绑定版（双轨制）

> 日期：2026-10-16 ｜ 状态：**方案待评估**（未实施）
> 背景：现有 v2.0.17 授权码不绑设备，一码可无限台机器使用 → 无法防止二次贩卖。

---

## 0. 结论先行

| 项 | 结论 |
|---|---|
| 技术能否"杜绝"二次贩卖 | **不能**。PyInstaller 打包的 Python 字节码可反编译，任何客户端校验都能被 NOP 掉。技术只能**提高门槛 + 提供追溯证据** |
| 推荐方案 | **双轨制**：现有通用版（不绑）继续卖；新增**设备绑定版**给高价客户 |
| 核心机制 | 授权码内嵌**设备指纹哈希**，换机需重新申请（保留审核痕迹） |
| 最大风险 | **售后负担增加**（客户换机/重装要找你）+ **向后兼容**（已发出的 4 个码不能失效） |
| 不推荐 | 联网激活/心跳（与"便携离线"定位冲突，体验损失 > 防转卖收益） |

## 1. 威胁模型（先想清楚防谁）

| 攻击者 | 能力 | 是否能防住 |
|---|---|---|
| **普通客户转卖** | 把收到的 exe + 授权码打包卖给第三人 | ✅ **能防**（本方案主要目标：码绑设备，第三人用不了） |
| **有心的二手商** | 同上 + 承诺"帮买家远程激活" | ⚠️ 部分（每次换绑都留记录，你能发现异常频次并拒绝） |
| **会逆向的人** | 反编译 `license.py`，改掉档位判定 | ❌ 防不住（任何纯客户端方案都防不住） |
| **大规模盗版组织** | 逆向 + 重新打包发布 | ❌ 防不住（但这类不是你的目标客户；且可用法律/水印追责） |

**方案定位**：防住第 1 类（占绝大多数），威慑第 2 类，对第 3/4 类靠水印追责 + 法律兜底。

## 2. 技术方案：设备指纹绑定

### 2.1 设备指纹怎么取

```python
# 采集三项硬件标识，拼接后哈希（避免任何一项单独可伪造/可搜到）
import subprocess, uuid, hashlib

def device_fingerprint() -> str:
    parts = []
    # ① CPU ID
    try:
        out = subprocess.run(["wmic", "cpu", "get", "ProcessorId"],
                             capture_output=True, text=True, timeout=10).stdout
        parts.append("".join(out.split()[1:]))          # 跳过表头
    except Exception:
        parts.append("")
    # ② 主板序列号
    try:
        out = subprocess.run(["wmic", "baseboard", "get", "SerialNumber"],
                             capture_output=True, text=True, timeout=10).stdout
        parts.append("".join(out.split()[1:]))
    except Exception:
        parts.append("")
    # ③ 系统盘序列号
    try:
        out = subprocess.run(["wmic", "diskdrive", "get", "SerialNumber"],
                             capture_output=True, text=True, timeout=10).stdout
        parts.append("".join(out.split()[1:])[:40])
    except Exception:
        parts.append("")
    raw = "|".join(parts)
    # 若全采集失败，退回 MachineGuid（注册表，重装系统才变）
    if not raw.strip("|"):
        raw = str(uuid.getnode())
    return hashlib.sha256(raw.encode()).hexdigest()
```

**稳定性的关键问题**：

| 硬件标识 | 换硬盘 | 换主板 | 重装系统 | 结论 |
|---|---|---|---|---|
| CPU ID | 不变 | 可能变 | 不变 | ✅ 较好 |
| 主板序列号 | 不变 | 变 | 不变 | ✅ 较好 |
| 硬盘序列号 | **变** | 不变 | 不变 | ⚠️ 换硬盘会失效 |

**缓解设计**：采集三项 → 允许**两项匹配即通过**（容忍单项硬件更换）。
这样换硬盘/换主板（单项）不会失效，只有"整机换"才需要重绑。

### 2.1.1 ★实测结果（2026-10-16，本机 Windows 10 + Python 3.11）

```
✅ cpu           'BFEBFBFF000806C1'
✅ board         'PM017021AS005618'
✅ disk          '0000_0000_0000_0000_0000_0034_1020_1067.'
✅ machine_guid  'cdec5d04-b694-4dd9-b549-2c1c258af7b4'
采集成功 4/4 项
展示用设备码: 4770-0AEB-18B6-1AB4
```

**★关键发现：本机 `wmic` 已不可用**（所有调用都走了 PowerShell CIM 回退）。
说明 CIM 回退**不是可选项，是必需项**——实现时必须两条路径都写，
且优先直接调 CIM（wmic 在新系统上正在消失）。

> 注意：`PowerShell CIM` 调用有明显开销（每次约 200-500ms），
> 3 项串行采集可能耗时 1-1.5s。GUI 上应在**点击"显示设备码"时才采集**
> （不在启动时采），避免拖慢软件启动。

### 2.2 码结构扩展（**必须向后兼容**）

现状：`15 字节 = 5B 载荷 + 10B HMAC`，载荷 `ver(1) | tier(1) | days(1) | rand(2)` 已满。

**新方案：按 ver 区分长度**

```
ver=1（现有，已发出的 4 个码）：5B 载荷，不绑设备 → 继续可用
ver=2（新版，设备绑定）：
    16 字节 = 11B 载荷 + 10B HMAC ... 太长，码会变 40+ 字符

  更优：把 HMAC 缩到 8B（安全边际仍足够：2^64 空间，离线猜码不现实）
    19 字节 = 11B 载荷 + 8B HMAC
    载荷: ver(1) | tier(1) | days(1) | devhash(8)
    码体 base32(19B) = 31 字符，加前缀与分组 ≈ 42 字符
```

**校验逻辑（向后兼容）**：

```python
def verify_code(code):
    blob = b32decode(code)
    ver = blob[0]
    if ver == 1:
        # 老逻辑：5B 载荷 + 10B MAC
        ...  # 现有代码不动
    elif ver == 2:
        # 新逻辑：11B 载荷 + 8B MAC
        payload, mac = blob[:11], blob[11:19]
        if not hmac.compare_digest(mac, _mac(payload, ver=2)):
            return None
        devhash = payload[3:11]
        # 绑定校验：本机指纹前 8 字节 == devhash？
        if devhash != device_fingerprint()[:8]:
            return None          # ← 设备不符，拒绝
        ...
```

**关键**：`_mac()` 的 `_MSG_PREFIX` 按 ver 区分（`SPHDLv1` / `SPHDLv2`），
避免跨版本签名互窜。

### 2.3 发码流程（设备绑定版独有）

```
客户第一次用：
  ① 客户装软件 → 点「🔑 授权管理」
  ② 弹窗新增一块「本机设备码」：
       设备码: A3F8-91C2-B7E4-5D9A          [📋 复制]
       把此码发给卖家，获取绑定本机的授权码
  ③ 客户把设备码发给你（微信/QQ）
  ④ 你用工具生成绑定码：
       python tools/license_tool.py gen 2000 --device A3F8-91C2-B7E4-5D9A
  ⑤ 客户粘进去 → 校验设备匹配 → 生效
```

**你侧新增的记录表**（防转卖追责的核心）：

```
licenses.jsonl（作者侧，不入库、自行保管）
  {"code":"SPHDL-...","tier":2000,"device":"A3F8-...","customer":"张三","phone":"138****1234","issued":"2026-10-16","note":"微信下单"}
```

有了这张表：
- 同一设备码被多个"客户"申请 → 说明有人在批量转卖 → **拒绝 + 拉黑**
- 市面上出现某码 → 查出是谁泄露的 → **追责/停止售后**

### 2.4 换绑流程（售后负担的来源）

```
客户换电脑 → 新设备码变了 → 授权失效
  → 客户联系你 → 你确认是老客户 → 生成新绑定码
  → 记一条换绑日志（同一客户第 N 次换绑）
```

**约束建议**：明确"免费换绑 N 次/年"（如 2 次），超出收工本费 → 既减负担又防滥用。

## 3. 双轨制怎么落地

| | 通用版（现有） | 设备绑定版（新） |
|---|---|---|
| 用途 | 低档位（轻量/标准）走量 | 高档位（专业/旗舰）高价 |
| 授权码 | ver=1，不绑设备 | ver=2，绑设备 |
| 包 | 现有 `release.py` 产物 | 同包（**同一份代码支持两种码**） |
| 客户体验 | 粘码即用 | 多一步"发设备码换绑定码" |
| 防转卖 | 无 | 强（码换机即失效） |

**关键：不需要打两个包** —— 同一份 exe 同时支持 ver=1 和 ver=2 的码。
用哪个版本的码，由你发给客户时决定。

这样：
- 已发出的 4 个 ver=1 码继续有效（不破坏现有客户）
- 高端客户发 ver=2 码，享受绑定保护
- 代码只有一套，维护成本低

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| **售后负担增加** | 客户换机/重装都找你 | 明确"免费换绑 2 次/年"；文档写清换绑流程 |

| **反编译绕过** | 会逆向的人改掉校验 | 接受（任何客户端方案都防不住）；靠水印追责 |
| **WMIC 弃用** | Win11 24H2+ 无 wmic | 必须实现 PowerShell CIM 回退 |
| **老码兼容出错** | 已发出的 4 个码失效 → 严重事故 | 写专项测试：ver=1 码在 ver=2 逻辑下仍校验通过 |

## 6. 诚实的边界声明

**本方案能做到**：
- ✅ 普通客户转卖 → 买家拿到码用不了（设备不匹配）
- ✅ 发现转卖 → 有码表可查，知道是谁泄露
- ✅ 一码一机，转卖价值大幅下降

**本方案做不到**：
- ❌ 阻止反编译（Python 字节码可改）
- ❌ 阻止"帮买家远程激活"的高级二手商（但你能看到异常频次）
- ❌ 完全免除售后（换绑仍需人工）

**补充建议（非技术，往往更有效）**：
1. **定价策略**：让转卖无利可图（单机价贴近客户心理价位）
2. **服务绑定**：承诺"包更新+包答疑+包换机"，转卖者给不了
3. **许可条款**：明确"授权仅限本人单机使用，禁止转售"
4. **正版自动更新**：让盗版永远是旧版（体验差异）

## 8. 追加建议：发码台账（水印追溯）【强烈建议一起做，成本近零】

设备绑定防的是"码被复用"，但**如果对方直接转发整个软件包呢**？
所以再加一层**追溯**：你手里维护一张「码 → 客户」台账。

### 台账格式（作者侧，不入库、自行保管）

`licenses.jsonl`（每行一条，append-only）：
```jsonl
{"code":"SPHDL-0420-07S0-G286-DTC2-J7DH-401W","tier":20000,"device":"4770-0AEB-18B6-1AB4","customer":"张三","contact":"微信:zhangsan","issued":"2026-10-16","price":199,"note":"旗舰版永久"}
{"code":"SPHDL-0410-0WRK-MS6V-XA9S-8JDK-47S4","tier":1000,"device":"","customer":"李四","contact":"QQ:1234567","issued":"2026-10-16","price":49,"note":"标准版-通用版不绑机"}
```

### 能解决什么问题

| 场景 | 台账的作用 |
|---|---|
| 市面上出现某码 | 反查 → 知道**是哪个客户泄露的** → 追责/停止售后 |
| 同一设备码被多个"客户"申请 | 说明有人批量转卖 → **拒绝 + 拉黑** |
| 客户说"我是老客户要换绑" | 查台账确认 → 防冒名 |
| 统计销量/档位分布 | 顺带得到经营数据 |

### 实现成本

**几乎为零**：`tools/license_tool.py gen` 时多写一行 jsonl 即可（约 20 行代码）。
台账**只存作者侧**，不入库、不随包分发。

> 与设备绑定的关系：**绑定是"锁"，台账是"眼睛"**。
> 只有锁没眼睛 → 转卖者换个说法你也不知道；
> 有眼睛没锁 → 你知道是谁卖的但拦不住。
> **两个一起做才是完整防护。**

### 台账文件位置建议

```
E:\myHermesWorkSpace\_archives\keys\licenses.jsonl     ← 与密钥备份同目录，方便统一保管
（或在项目外另建 licences/ 目录）
```
⚠️ 台账含客户联系方式（PII），**绝不入库、绝不放交付包**。
