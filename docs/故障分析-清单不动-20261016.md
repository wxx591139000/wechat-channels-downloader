# 故障分析报告 — 清单拉到 3000 条后删记录→清单不动

> 日期：2026-10-16 ｜ 报告对象：sphdl v2.0.17 ｜ 报告人：Hermes
> 用户报告（朋友机）：
> 1. 旗舰版（2 万条档）正常下到清单 **3000 个**
> 2. **删掉了所有记录**
> 3. 去掉了「下载图片」的 √
> 4. 重新打开视频号进行捕捉 → **视频清单不动了**
> 5. 把软件删掉重新安装 → 打开嗅探、打开视频号 → **清单依然拉不动**

---

## 一、结论：两个**互不相同**的原因叠加

| # | 现象 | 根因 | 影响范围 |
|---|---|---|---|
| **A** | 步骤 1–4：删记录后清单不动 | **`addon.seen` 捕获去重集合在删记录时未清空**（真 BUG，已复现） | 内存内有效；**重启软件即消失** |
| **B** | 步骤 5：重装后依然拉不动 | **非 BUG，是操作顺序**：「启动嗅探」之前视频号页面已打开，钩子注入 0 次 | 需按正确顺序操作 |

**为什么是两个原因**：
`seen` 是**纯内存集合、不落盘**（`addon.py:205`），所以**重装/重启必然清空它**。
既然重装后仍拉不动，说明步骤 5 已经不是 A 导致的，而是 B（或环境问题）。

---

## 二、根因 A（真 BUG，已复现）

### 证据（本机复现实验）

```
【阶段1】捕获 50 条
    addon.seen = 50      GUI 列表 = 50

【阶段2】删掉所有记录（走真实 GUI 删除链路）
    addon.seen = 50      ★ 未被清理
    GUI 列表   = 0
    GUI _vid_index = 0   ← GUI 侧清了

【阶段3】重新捕获同样的 50 条
    日志：⏭ 重复视频（已捕获过），跳过: 视频0 … 视频49   ← 全部跳过
    GUI 列表 = 1         ★ 复现：清单几乎不动
```

### 机制

```
addon.py:205    self.seen = set()            # (video_id) 去重集合，纯内存
addon.py:546    with self._seen_lock:
                    if key in self.seen:
                        logger.info("⏭ 重复视频（已捕获过），跳过")
                        return           # ← 直接返回，永不入列表
                    self.seen.add(key)
```

- `seen` 只**增**不减；唯一的移除动作在 `addon.py:573`（满档拒收时 `discard`）
- `gui.py` 的 `_drop_records_ui()`（删记录的统一入口）**只清 GUI 侧**的
  `_vid_index` / `_url_to_rid` / Treeview 行，**不通知 addon 清 `seen`**

### 为什么"删记录"会触发

用户删掉 3000 条记录后，`seen` 里仍留着那 3000 个 key。
重新打开视频号时，看到的还是同一批视频 → **全部命中 `seen` → 全跳过**。

**这解释了"清单不动"**，而且**只在"删记录后不重启"时出现**。

### 修复方案（与既有修复对称，改动小）

`_drop_records_ui` 已有 GUI 侧清理逻辑，现在**补上通知 addon**：

```python
# addon.py 新增方法
def release_seen(self, video_ids):
    """删记录后释放 seen 名额，使这些视频可被重新捕获。"""
    with self._seen_lock:
        for vid in video_ids:
            if vid:
                self.seen.discard(vid)
                self._dedup_logged.discard(vid)

# gui.py 的 _drop_records_ui 里补一行
def _drop_records_ui(self, rec_list):
    for rec in rec_list:
        ...
    if rec_list:
        self._after_records_removed()
        # ★ 新增：释放 addon 侧去重名额
        self.addon.release_seen(r.video_id for r in rec_list if r.video_id)
```

**注意**：还要处理「删除全部记录」时 `seen` 里有、但 list 里已无的残留 key
（例如满档被拒的视频曾经进了 seen）。建议**「删除全部记录」直接 `seen.clear()`**。

**对称性**：v2.0.17 我们已经修了「满档拒收时 addon 撤回已见标记」（`addon.py:573`），
本次是同一类问题在**删记录路径**上的遗漏 → 属**同一根因的第二个入口**。

## 三、根因 B（非 BUG，操作顺序）

### 判定依据

日志特征（你机器上午遇到的一模一样）：
```
💓 嗅探运行中 | 钩子数据 无 (心跳×0 / 数据×0) | 页面注入 0 次 | 捕获 0 个
```

**`页面注入 0 次`** = 代理没能把捕获钩子注入页面。

### 原因

微信视频号是**单页应用**。如果页面在**点「启动嗅探」之前**就已打开，
它走的是**本地缓存**、不再走网络 → 代理**没有机会注入钩子**。

### 正确操作顺序（★必须按此顺序）

```
① 先点「启动嗅探」→ 等状态栏显示「嗅探: 运行中」
② 完全关闭视频号页面（不是刷新！是整个关掉）
③ 重新打开视频号 → 页面重新走网络 → 代理注入钩子
④ 播放视频 → 捕获成功
```

### 为什么"重装软件"解决不了

重装只换了 exe，**视频号页面仍然是在启动嗅探前就打开的** →
钩子依然注入不进去 → 现象完全一样。**这是操作顺序问题，不是安装问题。**

## 四、给用户的自助诊断（发给他）

```
如果清单不动，按顺序检查：

1. 看软件界面左下角状态栏「钩子」那一项
   · 显示「钩子: 无 ⚠」或「页面注入 0 次」（日志里）
     → 是操作顺序问题：先启动嗅探，再【完全关闭】视频号，再重新打开
   · 显示「钩子: 3s前」（正常有数据）
     → 是去重问题，重启软件即可（或升级到修复版）

2. 日志区看有没有大量「⏭ 重复视频（已捕获过），跳过」
   · 有 → 是 seen 残留（本次 BUG），重启软件可绕过

3. 两个都没有、但就是不动
   → 把 logs/sphdl.log 发给开发者
```

**临时绕过方法（给当前 v2.0.17 用户）**：
- **重启软件**（清空 `seen`）→ 解决 A
- **严格按「先嗅探→再重开视频号」**→ 解决 B

## 六、遗留疑问（需用户补充信息才能确认）

1. **「下载图片」开关是否参与了**？
   从代码看，关闭它只影响**图片**（`vd.is_image` 时跳过），**不影响视频捕获**。
   所以它应该不是原因（复现实验也证实：关闭后视频仍能捕获）。
   但用户把它和"删除记录"一起操作了，可能是巧合。

2. **"删掉所有记录"的具体操作是哪个按钮**？
   「删除全部记录」/「清空已完成」/「删除记录」（多选删除）？
   三者都走 `_drop_records_ui`，所以都会触发 A。**但若能拿到确切按钮，可确认路径。**

3. **重装时的具体做法**？
   · 只换成新的 exe 文件（同目录）→ `records.json` 可能残留
   · 整个目录删掉重新解压 → `records.json` 一并清掉
   这决定重装后 `_vid_index` 是否被旧数据重建。

4. **最有价值**：让他把 `logs/sphdl.log` 发来。
   一次就能分清是 A（重复视频刷屏）还是 B（页面注入 0 次）。
