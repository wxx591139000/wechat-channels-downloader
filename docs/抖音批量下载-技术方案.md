# 抖音批量下载 · 技术方案与限流对策

> 版本：v2.4.1（2026-10-26）
> 需求来源：客户「希望有像视频号一样的抖音批量下载工具」
> 当前阶段：**方案 A（粘贴链接）已完成**，方案 B（输入主页批量抓）待做

---

## 一、技术路线选型（全部实测，不是推测）

### 试过但不可行的

| 方案 | 实测结果 |
|---|---|
| `yt-dlp` 直下 | ❌ `HTTP 403` + `Fresh cookies (not necessarily logged in) are needed` |
| `yt-dlp --cookies-from-browser edge` | ❌ `Could not copy Chrome cookie database`（浏览器占用数据库文件） |
| `yt-dlp --cookies-from-browser chrome` | ❌ `Failed to decrypt with DPAPI`（Chrome 127+ 加密策略变更） |
| 老代码（requests + playwright 取 cookie 再调 API） | ⚠️ 可行但要 `headless=False` 开窗口，且没有批量 |
| 手机分享页 `iesdouyin.com/share/video/` | ❌ `_ROUTER_DATA` 里没有 `play_addr`（数据走客户端渲染） |

### 最终采用：Playwright 读页面自己的响应

```
打开 https://www.douyin.com/video/{id}
  → 页面自己发起 aweme/v1/web/aweme/detail/ 请求并返回 200
  → 我们从 response 事件里读它的 JSON
  → 取 video.play_addr.url_list[0]
```

**核心优势：签名由页面自己算，我们不需要破解 `a_bogus` / `X-Bogus`。**

签名算法随时会变，破解意味着永远在追版本。读页面响应则不受影响。

### 实测确认的关键事实

| 项 | 结论 |
|---|---|
| `play_addr` 是什么 | **音视频合一 MP4**（实测 1080x1920、30.54MB、140.2 秒、h264 + aac） |
| 需要 ffmpeg 吗 | **不需要**（省 30~80MB，也省掉一堆合并失败问题） |
| 下载需要 cookies 吗 | **只需要 `Referer: https://www.douyin.com/`**（只带 UA → 403；UA+Referer → 206） |
| 需要登录吗 | 不需要，但**登录后限额高一个数量级** |
| 需要内置 Chromium 吗 | **不需要**，用 `channel="msedge"` 驱动系统 Edge（省 150MB） |
| **需要装 CA 证书吗** | **完全不需要**（我们自己开浏览器，不做 MITM） |

**最后一条最重要**：视频号必须 MITM（要在微信 webview 里注入 JS），
而抖音不需要 —— 直接绕开了「证书装不上 → 客户退款」那个坑。

## 二、限流问题与五层对策

### 限流特征（实测）

```
未登录状态连续请求 20+ 次
  → aweme/detail 开始不返回数据
  → 页面卡在「视频数据加载中」
  → 但首页仍 HTTP 200、无验证码
  → 静置一段时间后自行恢复
```

**判定：这是「详情接口的 IP 级限流」，不是全站封禁。**

对比验证：
- `https://www.douyin.com/` 首页 → 200 正常，无 captcha
- 带窗口模式 / headless 模式 → 表现一致（**与浏览器模式无关**）

### 五层对策

| # | 对策 | 实现 | 效果 |
|---|---|---|---|
| ① | **登录态复用** | 「登录抖音」按钮 → 有窗口扫码 → `launch_persistent_context(user_data_dir=...)` | 最有效，限额高一个量级 |
| ② | 分级节流 | 未登录 8~15 秒/条、单批 ≤10；已登录 3~6 秒/条、单批 ≤50 | 直接降低触发概率 |
| ③ | 失败冷却 | 连续 2 条失败 → 冷却 60 秒（可被「停止」立即中断） | 防止越刷越死 |
| ④ | 解析缓存 | 6 小时内同视频不再请求（`douyin_cache.json`） | 重复解析零消耗 |
| ⑤ | 双数据源 | detail 接口无数据时，退回读页面自身 media 流 | 兜底 |

### 登录态存放

```
%LOCALAPPDATA%\sphdl\douyin_profile\
%LOCALAPPDATA%\sphdl\douyin_cache.json
```

**放在用户级目录的理由**：换软件版本不丢登录态（和授权码同一套思路）。

### 隐私承诺（必须写进客户文档）

- 登录态只保存在客户本机，**不上传**
- 本工具**不读取账号内容**（只读视频公开数据）
- 随时可点「退出登录」删除本地 profile

## 三、给客户的使用建议（SOP 素材）

| 情况 | 建议 |
|---|---|
| 第一次用 | **先点【登录抖音】** |
| 一次下很多 | 分批，每批 10~20 条，中间歇几分钟 |
| 看到「限流」提示 | 别连点，等 10 分钟再试 |
| 长时间大量下载 | 分几个时间段 |

**关键点**：**已解析成功的地址，下载不受限**（走 CDN，不查详情接口）。
所以「解析一次、慢慢下」是最省限额的用法。

## 四、已知限制

| 限制 | 说明 |
|---|---|
| 限流不能 100% 消除 | 只能降低概率。极端情况仍需等待 |
| 首次真实环境未复验 | 开发期对抖音发了 20+ 次请求触发限流，验证时全部失败。逻辑已用伪造数据全覆盖（53+39 项） |
| 包体 30MB → 68.6MB | playwright driver 104MB（压缩后 +38MB）。可用 CDP 直连系统浏览器优化，但有风险 |
| 方案 B 未做 | 主页批量抓需要登录 + 翻页，风控更高 |

## 五、验证工具

```bash
# 源码环境
python main.py --selftest-douyin

# 打包后的 exe（关键！验证 PyInstaller 没打坏 playwright）
微信视频号下载器.exe --selftest-douyin
```

自检覆盖：模块导入 / playwright 导入 / driver 存在 /
**真正启动一次浏览器** / 配置目录 / 链接解析。

**这条自检存在的理由**：PyInstaller 打包后 playwright 经常因为
driver 目录没被完整收集而报 `Executable doesn't exist`。
打包机上通过 ≠ 客户机器能用。
