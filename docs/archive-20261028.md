## 三、三个核心技术结论

### ① 视频统计数不在 objectDesc 里，在兄弟键上

```json
{ "id": "...",
  "object_desc": { 12 个字段，一个统计数都没有 },
  "like_count": 135, "forward_count": 94,
  "comment_count": 0, "fav_count": 527 }
```

**连带两个坑**：数据藏在两层 JSON 字符串里；`object` 是 list。

**教训**：不要猜数据结构。本次猜了 5 轮（30+ 个字段别名全不中），
正确做法是第一步就把完整响应体存下来看。

### ② 抖音不需要 CA 证书

| | 视频号 | 抖音 |
|---|---|---|
| 抓取方式 | MITM 劫持微信流量 | 自己开浏览器读页面响应 |
| 装证书 | 必须 | **不需要** |

签名由页面自己算，不用破解 `a_bogus` / `X-Bogus`。
这直接绕开了「证书装不上 → 客户退款」那个坑。

**打包**：用系统 Edge（`channel="msedge"`），不打包 Chromium（省 150MB）；
包体 30MB → 68.6MB（playwright driver 占 38MB 压缩后）。

### ③ 点赞能力位必须走「能力位」而不是「产品线」

产品线互斥（一个码只解锁一条），做成 `product=4` 会导致客户买了点赞
就不能再用视频号 —— 卖不出去。

所以新增 **ver=5 码型 + caps 字节**：

```
ver(5) | tier | days//8 | product | caps | maxdev | rand(2)
                                    ↑ bit0 = 点赞增强包
```

老码 ver=1/2/3/4 靠首字节分流，caps 恒为 0，**完全不受影响**。

## 九、本轮最重要的两条工程教训

### ① 测试假绿比代码 bug 更危险（连续踩两次）

| 事故 | 表现 | 真因 |
|---|---|---|
| 勾选框 ✓ | 测试 20/20 全过，实际页面没有 ✓ | 按 `<style>` 抽 CSS，但真实 CSS 是模块常量 → 抽到空串，页面裸奔 |
| 手机 502 | 函数测试 22/22 全过，部署"成功"，页面却 500 | 只测了 `code_label()` 函数，没测「页面能不能打开」 |

**共同点**：测的是"我以为的那部分"，不是"用户实际走的那条路"。

**已固化**：
- `verify_cap_checkbox_visual.py` 断言「抽到的 CSS 长度 > 2000 且含关键规则」
- `verify_admin_routes_smoke.py` 进程内起服务，逐个打所有路由

### ② 存储格式不能假设

`config.license_codes` 真实是 **dict**（`{"1": "码A", "2": "码B"}`），
我按 list 遍历 → 已授权客户仍显示未授权。

**更麻烦的是**：测试也按 list 写 → 测试和实现一起错，还互相"验证"通过。
改成按真实 dict 格式写测试后立刻暴露。
